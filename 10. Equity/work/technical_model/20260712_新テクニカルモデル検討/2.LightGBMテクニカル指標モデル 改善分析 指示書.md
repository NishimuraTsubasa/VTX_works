````markdown
# VRPレジーム条件付きモデル 再設計・OOS検証指示書

## 1. 目的

12カ国の株価指数を対象としたクロスセクショナル予測モデルについて、これまでの分析から以下が確認された。

- 各国で共通のVRP系列を使用している
- VRP単体には各時点のクロスセクショナル分散がない
- 一方で、VRPの水準によって各テクニカル指標のRank ICが大きく変化する
- High VRP局面ではBP、DIS25、MOM14等の逆張り効果が強まる
- `rv_shock_20d` のようにVRP RegimeによってRank ICの符号自体が反転する特徴量も存在する
- `VRP × Local Feature` のInteractionには一定の追加予測力が確認された
- Rolling VRP Betaには現時点で明確な追加価値が確認できない
- 単体特徴量の予測力は20営業日より1〜5営業日に集中している
- 12資産しか存在しないため、複雑なモデルは過学習しやすい

以上を踏まえ、本フェーズでは、

> **VRPを単体Alpha Factorとして利用するのではなく、各テクニカル特徴量の効果を変化させるGlobal Regime Variableとしてモデル化する**

ことを目的とする。

---

# 2. 基本モデル方針

最終的なモデル構造の第一候補を以下とする。

$$
\hat{R}_{i,t}^{5D}
=
f
\left(
X_{i,t},
RV_{i,t},
VRP_t,
VRP_t \times X_{i,t}
\right)
$$

ここで、

- $X_{i,t}$：各国固有のテクニカル特徴量
- $RV_{i,t}$：各国固有のRealized Volatility関連特徴量
- $VRP_t$：全12カ国共通のGlobal VRP
- $VRP_t \times X_{i,t}$：Global Regime × Local Feature Interaction

とする。

重要：

**VRP単体によって国を順位付けしようとしない。**

VRPの役割は、

```text
Country Ranking Signal
```

ではなく、

```text
Global Market State
```

とする。

# 3. 主目的変数

## 3.1 5営業日相対リターンを第一候補とする

これまでのホライズン分析では、単体特徴量Rank ICが1〜5営業日に集中していた。

20営業日では予測力が大きく減衰しているため、主目的変数を5営業日相対リターンへ変更する。

まず5営業日絶対リターンを作成する。

$$
R_{i,t}^{5D}
=
\frac{P_{i,t+5}}{P_{i,t}}-1
$$

```python
df = df.sort_values(["country", "date"])

df["future_return_5d"] = (
    df.groupby("country")["price"].shift(-5)
    / df["price"]
    - 1
)
```

次に各時点の12カ国平均を除去する。

$$
Y_{i,t}
=
R_{i,t}^{5D}
-
\bar{R}_{t}^{5D}
$$

```python
df["cs_mean_return_5d"] = (
    df.groupby("date")["future_return_5d"]
    .transform("mean")
)

df["target_relative_5d"] = (
    df["future_return_5d"]
    - df["cs_mean_return_5d"]
)
```

主ターゲット：

```text
target_relative_5d
```

とする。

# 5. VRPの作成方法

VRPは絶対水準だけでなく、過去と比較した状態を表す変数として使用する。

最低限以下を作成する。

```text
global_vrp
global_vrp_change
global_vrp_z
global_vrp_percentile
```

---

## 5.1 VRP Z-score

過去252営業日を使用する。

$$
VRPZ_t
=
\frac{
VRP_t-\mu_{t,252}
}{
\sigma_{t,252}
}
$$

```python
vrp = (
    df[["date", "global_vrp"]]
    .drop_duplicates("date")
    .sort_values("date")
    .copy()
)

window = 252

vrp["vrp_mean"] = (
    vrp["global_vrp"]
    .rolling(window)
    .mean()
)

vrp["vrp_std"] = (
    vrp["global_vrp"]
    .rolling(window)
    .std()
)

vrp["global_vrp_z"] = (
    (vrp["global_vrp"] - vrp["vrp_mean"])
    / vrp["vrp_std"]
)
```

必ず過去情報のみを使用すること。

def classify_vrp(z):

# 9. Explicit Interaction Features

本モデルの中心となる特徴量。

以下をまず作成する。

```text
vrpX_BP
vrpX_DIS25
vrpX_MOM14
vrpX_RSI14
vrpX_rv_shock_20d
vrpX_rv_20d
```

Python例：

```python
interaction_features = [
    "BP",
    "DIS25",
    "MOM14",
    "RSI_14",
    "rv_shock_20d",
    "rv_20d",
]

for feature in interaction_features:

    df[f"vrpX_{feature}"] = (
        df["global_vrp_z"]
        * df[feature]
    )
```

Interactionを全特徴量について大量生成しないこと。

過学習防止のため、候補を限定する。

---

# 10. Interactionの経済的解釈

例えば、

$$
Score
=
\beta_1 BP
+
\beta_2
(BP \times VRP)
$$

の場合、

BPの実効的な係数は、

$$
\frac{\partial Score}{\partial BP}
=
\beta_1
+
\beta_2VRP
$$

となる。

したがってVRPが上昇すると、

- BPの効果が強まる
- BPの効果が弱まる
- BPの符号が反転する

といった状態を表現できる。

今回観測されたRegime依存性を直接モデル化できる。

# 17. 第一候補はRidge

最初にRidge Regressionを使用する。

理由：

- 12資産しかない
- Explicit Interactionをこちらで作成できる
- LightGBMよりモデル構造が安定しやすい
- 係数を直接確認できる
- Regime依存性を解釈しやすい
- 過学習を抑制しやすい

モデル：

$$
\hat y
=
\beta^\top X
+
\gamma^\top(X \times VRP)
$$

とする。

# 20. LightGBMはShallow Modelとする

LightGBMも比較するが、モデル複雑度を抑える。

方向性：

```text

min_data_in_leaf   : 大きめ
feature_fraction   : 低め
bagging_fraction   : 低め
lambda_l1          : 強め
lambda_l2          : 強め
```

例：

```python
params = {

# 23. 将来候補：Soft Regime Model

Interaction ModelがOOSでも改善した場合のみ、次の段階としてSoft Regime Modelを検討する。

概念：

$$
Prediction_t
=
(1-g_t)
Prediction_t^{Normal}
+
g_t
Prediction_t^{High}
$$

ここで、

$$
g_t
=
g(VRP_t)
$$

はHigh VRPである確率または強度を表す。

VRPの変化に応じてモデルを滑らかに切り替える。

現段階では実装しない。

# 24. Walk-forward Validationを必須とする

今回のモデル評価は完全な時系列評価とする。

例：

```text
Train
↓
Validation
↓
Test
↓
Window更新
↓
再学習
```

Walk-forward方式を基本とする。

---

# 25. 特徴量選択は必ずTrain期間のみで行う

特に注意すること。

今回確認された、

```text
BP
DIS25
MOM14
RSI14
rv_shock_20d
```

などについて、全期間の結果を見て選択した場合、selection biasが含まれる可能性がある。

正式なOOS評価では各Walk-forward windowについて、

```text
Train
↓
Rank IC計算
↓
Regime IC計算
↓
Interaction候補選択
↓
モデル学習
↓
Validation/Test
```

とする。

未来のデータを特徴量選択に使用しない。

5営業日先リターンを使用するため、Train/Test境界付近でターゲット期間が重複する可能性がある。

概念：

```text

xxxxx

-----

Test
xxxxx

# 40. モデル採用条件

Regime Interaction Modelを採用するためには、少なくとも以下を満たすこと。

### 条件1

OOS Rank ICがBaselineより改善。

### 条件2

Top3-Bottom3が改善。

### 条件3

改善が特定の1期間だけに依存しない。

### 条件4

High VRPだけでなく全体として経済的価値がある。

### 条件5

Transaction Cost控除後でも改善。

### 条件6

Ridge / LightGBMなど複数手法で方向性が大きく矛盾しない。

# 41. VRPを残す条件

Global VRPを最終モデルに残すのは、以下のいずれかが確認された場合とする。

```text
1. VRP Regime別でモデル性能が明確に異なる
2. VRP × Local InteractionがOOS性能を改善
3. VRPを追加するとTop3-Bottom3が改善
```

VRP単体の係数やFeature Importanceが小さいことだけを理由に除外しない。

VRPはRegime Variableであるため、

**Interactionを通じた効果を重視する。**

---

# 42. VRPを除外する条件

以下の場合はVRPを最終モデルから除外する。

```text
VRP Regime差がOOSで再現しない
AND
VRP InteractionがOOSで改善しない
AND
Portfolio Performanceも改善しない
```

理論的な期待だけでVRPを残さない。
````
