目的：別チャットに引き継ぎ、既存Pythonコードを最小限変更して検証を進める。

## 0. 最初に守ってほしいこと

あなたは金融時系列予測・機械学習に詳しいPythonエンジニア兼クオンツリサーチャーです。添付する既存コード、設定ファイル、入力データ仕様、実験結果を実際に確認して、以下を実装してください。

**今回の目的は、予測スコアを大きくすることではありません。「同じ説明成分を使ったとき、Lassoの縮小をどこまで解除することが適切か」を、過去情報だけで検証することです。**

既存モデルの再現・監査を先に行い、新規モデルはLassoとOLSの混合型に絞ってください。Ridge、Elastic Net、Adaptive Lasso、PCA成分数変更などを、未検証の改善案として最初から再提案しないでください。

本書の数値は、ユーザーが提示した結果画像の転記です。元のExcel・予測時系列・コードを本書作成時に再計算したものではありません。実装担当者は原ファイルで照合してください。以下の実装設計は今回の追加提案であり、Kagkadis論文の原仕様そのものと主張しないでください。

## 1. 研究背景と、既に分かっていること

### 1.1 現在のモデル構造

参照研究はKagkadisらの「Factor Timing with Portfolio Characteristics」です。ユーザーの現行実装は、概ね次の構造です。正確な処理順、中心化、標準化、ラグ、推定窓はコードから確定してください。

```text
ファクターリターン
  → PCAによるPCリターンの抽出
  → ファクターポートフォリオの特性をPCの負荷量で集約
  → PLSによる説明成分の作成
  → Lassoによる説明成分選択・係数推定
  → PCリターン予測
  → 元のファクターリターンへの復元
  → ファクターティルト／LSS評価
```

「予測対象側のPCA主成分」と「説明変数側のPLS成分」を混同しないでください。今回固定して比較する選択集合は、各PCリターンを予測するためのPLS説明成分です。

### 1.2 既存の観測

Lassoでは係数がゼロ近傍になり、予測リターンの時間変動が小さくなりました。Ridgeでは変動幅は回復しましたが、予測精度は悪化しました。さらに、Post-Lassoの改善を調べた結果、単なる縮小解除だけでは説明できないことが分かっています。

画像上の評価対象はCore13、期間表示は2023年6月〜2026年9月、40か月です。この期間表示が「予測作成月」か「リターン対象月」かはコードで確認し、混同しないでください。

|---|---:|---:|---:|
| 現行Lasso | 0.0298 | 0.103 | 8.52% |
| 現行選択集合＋OLS | 0.0196 | 0.111 | 10.00% |
| 現行選択集合＋Bayesian Ridge | 0.0150 | 0.116 | 9.17% |
| CV選択集合＋Lasso | 0.0422 | 0.172 | 12.64% |

これらは画像から転記した参照値であり、新しい実装に数値を合わせるための調整目標ではありません。

### 1.3 今回の解釈

現行選択集合でのOLS化は、平均OOS R²を0.0298から0.0196へ悪化させています。一方、CV選択集合でのOLS化は0.0422から0.0554へ改善させています。したがって、**縮小解除の効果は選択集合に依存している**と解釈します。

CV選択集合ではOLSのR²・LSSが高い一方、Rank ICはLassoの方が高く、OLSが全指標で優位なわけではありません。順位予測とリターン水準の予測を分けて評価してください。

また、画像では次の注意点が報告されています。

- OLS同士で選択集合を変更した効果のHAC検定：未調整p値0.044。
- CV選択集合内でLassoをOLSにした追加効果：p値0.196。
- 改善の大きい3か月（2026年3月、2025年12月、2026年1月）を除くと、MSE改善が大幅に縮小。
- IS後半では、現行選択集合のOLS化によりR²が−0.0490から−0.2139へ悪化。
- 当時の選択集計には、実績未確定として扱われた2026年10月のLIVE予測が入り、41か月×5PC＝205件とされている。一方、予測精度評価は40か月。

検定方法やp値は原ファイルで確認してください。「有意差がない＝効果がない」「未調整p値が0.05未満＝改善が確定」と結論しないでください。少数月への依存も、直ちにモデルを却下・採用する根拠にしないでください。

## 2. 今回の実装範囲

主比較は次の3モデルです。

| ID | 説明成分の選択 | 係数推定 |
|---|---|---|
| `cv_lasso` | 既存のCV選択手順 | 元のLasso推定値 |
| `cv_post_lasso` | 同じCV選択手順・同じ集合 | 選択集合上でOLS再推定 |
| `cv_partial_relaxation` | 同じCV選択手順・同じ集合 | LassoとOLSの混合。混合比率のみ過去データで選択 |

現行Lasso・現行選択集合＋OLSは再現用の比較対象として残してください。Bayesian Ridgeは既存結果の補助比較にとどめます。Adaptive Lassoの追加調整、新しい非線形モデル、PC別の独立した混合比率、レジーム別混合比率は今回の対象外です。

PCA成分数、PLS成分数、特性定義、訓練窓、ファクター集合、取引コスト、配分ルールも、同時には変更しないでください。リーク・バグ修正が必要な場合だけ、修正前の再現結果と修正後の共通条件比較を分けてください。

## 3. Phase 0：既存実装の再現と監査

### 3.1 コードで確定する項目

各予測時点で使用するデータ、ラベルが確定する時点、特性の公開ラグ、PCAとPLSの推定範囲、標準化、切片、逆変換、Lassoの目的関数・alpha候補・選択基準を整理してください。

特に「CV選択集合」がどのように得られたかを明確にしてください。alphaをLassoの検証誤差で選んだのか、OLS再推定後の検証誤差で選んだのか、別の評価量かを確認します。選択手順の優劣と、選択基準・係数推定方法の組み合わせの優劣を混同しないでください。

既存表の各行でPCA、PLS、スケーリング、訓練観測まで共通だったかも確認してください。異なる場合、「純粋に選択集合だけを変えた効果」とは呼ばないでください。

### 3.2 再現結果の保存

既存コード・設定・入力データを変更せず、参照表を再生成してください。再現できない場合は、差分、原因候補、未確認事項を先に記録します。元ファイルは上書きせず、実行ID、設定、コード版、ライブラリ版、入力ファイルのハッシュを保存してください。

リークが見つかった場合は、`legacy_reproduction`と`leakage_corrected`を分け、修正後の全比較モデルを同じ条件で再実行してください。旧実装の基準値と新しいモデルだけを比較して改善を主張しないでください。

### 3.3 IS後半の定義

「モデル開発上のIS期間」と「各回帰の訓練観測」は区別してください。IS後半が時系列検証区間ならOLSで悪化しても矛盾しません。

同じ訓練観測・目的変数・説明行列・切片条件で通常の無制約OLSを行う場合、回帰目的変数に対する訓練SSEについては、数値許容誤差の範囲で次を確認してください。

\[
\|y-\widetilde X_S\hat b^{OLS}\|^2
\leq
\|y-\widetilde X_S\hat b^{L}\|^2.
\]

この性質を、復元後のファクター別平均R²や検証区間の誤差に、そのまま当てはめないでください。

## 4. 新規モデルの数式仕様

### 4.1 記号

予測作成時点をt、予測対象PCをk、PLS説明成分ベクトルをx_{k,t}、次期PCリターンをz_{k,t+1}とします。実際のホライズンが1か月以外なら、既存定義に合わせて時点を修正してください。

Lassoの正則化強度は`alpha_lasso`、縮小解除の混合比率は`rho`と命名してください。同じlambdaで両方を表現しないでください。

### 4.2 選択集合とLassoの端点

既存のCV選択手順を学習データだけに適用して、Lasso係数を得ます。

\[
\hat z^L_{k,t+1}
=\hat a^L_{k,t}+x_{k,t}^{\top}\hat\beta^L_{k,t},
\qquad
S_{k,t}=\{j:\hat\beta^L_{k,t,j}\neq0\}.
\]

実装上の非ゼロ判定は既存の数値許容誤差を確認して固定します。微小な非ゼロ係数を切り捨てる場合は、その影響を記録してください。

**Lasso側の端点は、選択時に得られた元のLasso推定値を使ってください。選択集合に絞った後にalphaを再選択して、別のLassoモデルへ変えないでください。**

### 4.3 OLSの端点

同じ学習データ、同じPLS座標、同じ選択集合上で、切片を含めて再推定します。

\[
(\hat a^{OLS}_{k,t},\hat\beta^{OLS}_{k,t,S})
=\arg\min_{a,b}
\sum_{s\in\mathcal T_t}
(z_{k,s+1}-a-x_{k,s,S}^{\top}b)^2.
\]

選択集合外の係数はゼロとします。混合モデルのためにPLSを作り直したり、別の特徴量を追加したりしないでください。

### 4.4 部分的縮小解除

\[
\hat\beta^{(\rho)}_{k,t}
=(1-\rho)\hat\beta^L_{k,t}
+\rho\hat\beta^{OLS}_{k,t},
\qquad 0\leq\rho\leq1.
\]

切片も同様に混合します。

\[
\hat a^{(\rho)}_{k,t}
=(1-\rho)\hat a^L_{k,t}
+\rho\hat a^{OLS}_{k,t}.
\]

したがって、同じ入力・同じ座標なら、予測値を混合する実装と一致します。

\[
\hat z^{(\rho)}_{k,t+1}
=(1-\rho)\hat z^L_{k,t+1}
+\rho\hat z^{OLS}_{k,t+1}.
\]

初期候補は`rho_grid = [0.0, 0.5, 1.0]`に固定します。rho=0はLasso、rho=1はPost-Lassoです。最初は各予測時点で全PC共通のrhoを一つ選びます。毎時点の更新は可能ですが、更新手順・候補・評価基準は事前固定してください。

この混合仕様はRelaxed Lassoの混合型実装を参考にしたものです。[1] glmnetのgammaはLasso側の重みであり、本書では`rho = 1 - gamma`に対応します。Rへの移植は要求しません。既存Python実装に追加してください。

### 4.5 元のファクターへの復元

復元は既存の逆変換を共通利用します。例えば、標準化後のリターンにPCAを適用している場合の一例は、

\[
\hat{\boldsymbol r}^{(\rho)}_{t+1}
=\boldsymbol\mu_t+D_tW_t\hat{\boldsymbol z}^{(\rho)}_{t+1}.
\]

ここでW_tは当該訓練期間のPCA負荷量、D_tはスケールの対角行列です。ただし、この式を現行実装・原論文の仕様と決めつけないでください。非中心化リターンへの射影など、現行仕様が異なる場合はその定義を明示して再現します。

全PCで共通rho、共通のアフィンな逆変換であれば、復元後の予測もLasso予測とOLS予測の同じ比率の混合に一致します。この等価性をテストしてください。クリッピング、順位化、ウェイト化はその後に共通処理し、係数混合と混同しないでください。

### 4.6 例外処理

選択集合が空の場合は、切片のみの予測とします。切片が訓練平均となる仕様なら平均を使い、無条件に予測ゼロへ置換しないでください。この場合、共通条件のLasso・OLS・混合予測が一致することを確認します。

OLSはQR分解・SVDなどを用い、正規方程式の逆行列を直接計算しないでください。ランク不足、残差自由度不足、収束失敗、欠損値、定数列への処理を評価前に固定してログ化します。OLSを黙ってRidgeへ置換したり、失敗した月だけ評価から削除したりしないでください。

## 5. 時系列検証：同じ集合を比較しつつ、未来情報を使わない

### 5.1 「選択集合を固定する」の意味

全期間で一つの集合を固定することではありません。**同じ予測時点・同じ検証分割において、Lasso・OLS・混合モデルが同じ説明成分を使う**という意味です。

各時点の過去データから選択集合は更新してよいですが、rho候補ごとに選択集合、PCA、PLS、alpha選択手順を変えてはいけません。

### 5.2 全工程を各学習区間の中に入れる

時系列方向に分割し、外側の予測対象より前に確定したラベルだけを学習に利用します。財務特性等は公開日時・更新ラグも確認してください。ラベルが重複するホライズンでは、利用可能時点に合わせてgap等を設定します。ランダムK-Foldは使わないでください。

各内側分割でも、学習を必要とする標準化、欠損補完、PCA、PLS、成分選択、係数推定を学習部分だけでfitしてください。[2] PLSは目的変数を使うため、外側訓練期間全体で一度作ったPLS成分を、内側CVへそのまま流用しないでください。[3]

同時点で利用可能な情報のみから計算するクロスセクション正規化と、期間全体から推定する標準化を区別してください。前者まで無条件に禁止せず、利用可能情報を確認します。

### 5.3 alpha選択とrho選択の入れ子

rho検証用の各学習区間で、既存の選択手順を最初から実行します。その手順自体がalphaのCVを必要とする場合、そのCVもrho検証区間を含めずに実施してください。

```text
外側：実際の予測時点 t
  内側：rhoを選ぶための時系列検証
    学習部分の中：必要ならalphaを選ぶための時系列CV
    同じ選択集合でLasso・OLSを学習
    内側検証部分に予測し、各rhoの誤差を記録
  内側検証の集計だけでrhoを決定
  外側の全学習データで選択手順と両端点を再学習
  決めたrhoで混合し、時点tの予測を保存
```

alphaを内側検証ラベルで選んでから、その同じラベルへの予測を「完全な学習外予測」と呼ばないでください。計算量を抑える場合は、同じ学習範囲のPCA・PLS・両端点・検証予測をキャッシュして再利用します。未来データを含むキャッシュを再利用しないでください。

### 5.4 rhoの選択基準

今回の新規設計では、復元後のファクター予測に対する、訓練分散で正規化した二乗誤差を主基準とします。これは追加提案であり、既存CVの評価基準と異なる場合は明示してください。

内側分割jの訓練データだけで計算したファクターnの分散をv_{j,n}、検証予測の集合をVとし、

\[
L(\rho)=\frac{1}{|V|N}
\sum_{(j,u)\in V}\sum_{n=1}^N
\frac{(r_{u,n}-\hat r^{(\rho,j)}_{u,n})^2}
{\max(v_{j,n},\epsilon)}.
\]

このLを最小化するrhoを選びます。epsilonはリターン単位に整合する正の下限値として設定ファイルに事前固定します。定数系列や欠損の扱いも共通化してください。数値許容誤差内で同点なら、小さいrhoを採用します。

PCごとのMSEを、そのまま元ファクターの平均R²と同じものとして扱わないでください。Rank ICやLSSは重要な評価指標ですが、今回rhoを選ぶ主目的へ事後的に切り替えないでください。

## 6. 評価期間の扱い

既存の40か月は、すでに研究で参照した探索期間として表示してください。その期間で最高成績だったrhoを選び、それを独立OOSの成績と主張しないでください。

まだ研究に使用していない期間が実際に存在する場合は、使用履歴を確認してから、未使用の最終検証期間として確保してください。過去に何度も見たデータを日付で分割し直しただけでは、未使用データにはなりません。

実績未確定の予測はLIVEとして別表示します。画像では2026年10月が当時未確定とされていますが、その状態を永久に固定せず、現在の実績データ有無を確認してください。実績が後日確定しても、事前保存された予測と後から作り直した予測を区別します。既存40か月の再現表へ黙って追加しないでください。

全予測に`forecast_origin`、`target_start`、`target_end`、`label_available_at`、`data_asof`、`evaluation_status`を保存してください。

## 7. 必須の評価と原因分解

### 7.1 予測精度と経済的評価

| 区分 | 必須項目 |
|---|---|
| 水準予測 | ファクター別MSE・MAE・OOS R²と、その平均 |
| 順位予測 | 月次横断Pearson IC・Rank IC。時系列ICとは分離 |
| 予測の性質 | 平均・標準偏差・符号的中率・校正・極端値頻度 |
| 経済的評価 | 費用控除前後LSS、算術年率、年率ボラティリティ、Sharpe、最大ドローダウン、turnover |
| 推定の状態 | alpha、rho、選択成分数、切片のみのPC割合、失敗・fallback件数 |

OOS R²は、過去情報だけによるベースラインを使い、定義を明記してください。

\[
R^2_{OOS,n}
=1-
\frac{\sum_u(r_{u,n}-\hat r_{u,n})^2}
{\sum_u(r_{u,n}-\hat r^{base}_{u,n})^2}.
\]

ファクター別R²の単純平均と、全ファクターをプールしたR²は別表示にします。平均R²の低下・上昇を、重みの異なるMSE指標の変化と同一視しないでください。

予測横断面が定数で相関を定義できない場合、無断でIC=0にしないでください。NaNと件数を報告し、比較可能な共通月の結果と利用可能月の結果を区別します。各モデルで有効な評価月が変わらないよう、分母・欠損処理を監査してください。

LSSの上位・下位の本数、13ファクターでの分位点丸め、同順位処理、グロス量、コスト、リスク調整は共通化します。算術年率と複利年率を混同せず、LSSはファクターL/S代理ポートフォリオであって実ファンド収益率ではない旨を記載してください。

### 7.2 月別損失差

比較Aに対するBの改善を、正の値が改善となる向きで定義します。

\[
d_{u,n}=(r_{u,n}-\hat r^A_{u,n})^2
-(r_{u,n}-\hat r^B_{u,n})^2.
\]

月別集計の重みは、比較対象の評価量に合わせて明記します。少なくとも「現行Lasso対CV-Lasso」「CV-Lasso対CV-OLS」「CV-Lasso対混合」「CV-OLS対混合」を保存してください。

月別損失差と累積差、年別差、勝率、中央値、改善・悪化上位月、各月の寄与を出力します。全期間を主結果とし、上位3か月除外などは事後的な感度分析と明記してください。改善月だけを取り除く分析に加え、全月のleave-one-month-outを確認し、都合のよい除外月を選ばないでください。

### 7.3 改善月の詳細

画像で指摘された3か月と、全月共通の集計について、実現値、各モデルの予測値、PC別予測、選択PLS成分、alpha、rho、ファクター順位、LSSウェイトを対応付けてください。予測変更が大きな誤予測を回避したのか、リターンの動きを積極的に当てたのかを確認します。

水準予測の改善は、e_A=r−予測A、delta=予測B−予測Aとして、次の恒等式でも確認できます。

\[
d=2e_A\,\delta-\delta^2.
\]

PC別の予測変更を追跡する場合、共通PCA基底で元ファクターへの寄与を計算してください。PC一つずつの置換によるMSE変化は交差項を含むため、単純合計が全改善と一致するとは限りません。

### 7.4 選択の安定性

同じ時点・同じPLS基底での選択一致率を確認してください。異なる時点の「第2PLS成分」等は、番号が同じでも方向が変わり得るため、番号だけで同一変数と判断しないでください。時点間の比較には元特性への負荷量・有効係数・共通観測上の予測などを使います。

係数がすべてゼロのPC比率は、分母が評価可能な40か月×PC数なのか、LIVEを含むのかを明示してください。

## 8. 統計検定の扱い

既存HAC検定の損失系列、ラグ数、片側／両側、標本数を確認してください。必要なら月次の損失差に対するHAC推定や、時間依存を考慮したブロック・ブートストラップを補助分析として実施します。

13ファクター×40か月を独立な520標本として扱わないでください。月を単位にファクター間・モデル間の対応を保ちます。検定する主要比較、ラグ・ブロック長の扱いは評価前に決め、複数比較と探索履歴も記録してください。

保存済み予測の損失差だけを再標本化した結果は、選択・学習工程全体の不確実性を再現するものではありません。何を固定した推論かを明記し、40か月での検定値だけから将来の優位性を断定しないでください。

## 9. 実装・保存要件

既存のフォルダ構成と実行方法を優先してください。単一スクリプトの既存実装なら、小さな関数・クラス追加で対応し、不必要に大型フレームワーク化しないでください。

設定ファイルでは少なくとも以下を管理します。

```yaml
experiment_name: fixed_support_partial_relaxation
rho_grid: [0.0, 0.5, 1.0]
rho_shared_across_pcs: true
rho_selection_metric: train_variance_scaled_factor_mse
tie_break_rho: smaller
preserve_existing_selector: true
refit_transforms_within_each_training_split: true
include_unrealized_labels_in_metrics: false
```

これに、既存のPCA・PLS・alpha選択設定、訓練窓、内側分割、epsilon、数値許容誤差、例外処理、取引ルールを明示的に追加してください。未確認の値を勝手に「既存設定」として埋めないでください。

予測・係数・設定・スプリットをCSV、Parquet、JSONなどで保存します。最低限、`predictions`、`coefficients_and_supports`、`cv_losses`、`monthly_loss_differences`、`model_comparison`、`data_audit`が追跡できるようにしてください。

モデル間で共通の評価関数を使い、型ヒント・docstring・乱数管理・再現可能な実行コマンドを付けてください。実行していないコードや検証していない実データ結果を「確認済み」と書かないでください。

## 10. 必須の受入テスト

| テスト | 合格条件 |
|---|---|
| rho=0 | 同じ条件のCV-Lasso予測に数値許容誤差内で一致 |
| rho=1 | 同じ条件のPost-Lasso予測に一致 |
| 切片・係数混合 | 予測値の直接混合と一致 |
| 復元の整合性 | 共通アフィン逆変換の条件下で、PC混合後の復元と復元後の混合が一致 |
| 同一選択集合 | 各時点・分割で3モデルの集合、基底、スケールが共通 |
| 選択集合が空 | 共通の切片予測となり、ゼロへの強制置換がない |
| 訓練SSE | 同じ回帰目的・条件ならOLSのSSEがLasso以下 |
| 未来データ改変 | 当該予測時点より後のデータだけを変更しても、既存時点の予測・設定が変わらない |
| 内側CVの範囲 | rho検証ラベルがPCA・PLS・成分選択・alpha選択の学習に入らない |
| スケーリング | 学習時のスケーラーを適用し、復元の中心化・単位が整合 |
| 評価対象 | 未実現ラベルを評価しない。共通期間の件数が一致 |
| 失敗処理 | 推定失敗や欠損の発生月が黙って評価から落ちない |
| 予測タイミング | forecast_origin、target、label_available_atが整合 |

合成データでの単体テストと、実データでの再現テストを区別して報告してください。

成果物は、修正済みPythonコード、設定ファイル、実行手順、テスト結果、再計算可能な予測・診断データ、Markdown診断レポートです。
